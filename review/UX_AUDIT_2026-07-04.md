# YEE Mobile — UI/UX Audit

**Date:** 2026-07-04
**Scope:** All 122 screenshots — 10 logical screens × iPhone / iPad / Android phone / Android tablet × light + dark.
**Method:** Multi-framework review (Nielsen 10 heuristics · Norman 7 principles · Krug · IxDF · visual-design · mobile craft · WCAG), grounded in the code packs under `review/packs/` and the token source `lib/design-system.ts`. A multi-agent pass reviewed Home, Places and Audit steps 1–2 with adversarial verification; the remaining core-loop screens (Execute, Audit domain/review, Reports, Report detail, Settings) plus tablet/dark variants were reviewed directly against the screenshots and code.

> **One-line verdict — Grade B−.** A polished, confident, phone-first product with a coherent visual voice and genuinely good field-ergonomics (thumb-zone footers, offline-first messaging, dyslexia font + text scaling). It is held back by three _systemic_ issues, each cheap to fix relative to its blast radius: (1) **fill color tokens are used as text** on soft surfaces — which the design system's own doc explicitly forbids — costing contrast across many screens; (2) **tablet layouts stretch full-width** and do not match the responsive system documented in `DESIGN.md`; and (3) on the **dark-mode audit-answering screen every unselected option renders in the mint "primary" color**, so nothing reads as unselected.

## Prioritized findings

### P1 — major (fix this sprint)

**P1-1 · Fill tokens used as text on soft surfaces (WCAG:Contrast, UI:Color, Nielsen:H4).**
`DESIGN.md` states plainly: _"Do not use fill tokens as text on soft backgrounds; use `tone.text` or the matching `*Text` token."_ Yet fill tokens appear as text in several places:

- **Home** — metric label chips and the big numbers in the 2×2 grid; the "READY FOR OFFLINE USE" heading uses the `success` fill (#5E9C83) as text on the `successSoft` wash (~2.6:1 — fails AA).
- **Places** — status pills ("DRAFT IN PROGRESS", etc.) use fill tokens as label text.
- **Execute** — "Ready for offline capture" uses `warning` (#C89A57) as text.
  _Fix:_ replace with `successText` #35735C / `warningText` #8A5F16 / `dangerText` #B2453A / `infoText` #4969A0 (dark: the `*Text` tokens already map to legible values). Systemic; a grep for fill-token usage in `Text`/`Paragraph` color props will find them.
  _Affected:_ all platforms, both themes (worse in light).

**P1-2 · Dark-mode audit options all read as "active" (Norman:Signifiers, Nielsen:H4, WCAG:Contrast).**
On `app/audit/[placeId]/[step].tsx` in dark mode (`iphone/dark · audit-domain-questions`, and every dark step capture), the unselected option labels — "Yes", "No", "Spring", "Summer" … — render in the mint `primary` (#7FBFA3). Because primary is also the selected/active accent, **nothing looks unselected**; an auditor tapping through 8 pages in the field can't tell answered from unanswered at a glance.
_Fix:_ unselected option text → `foreground` (#F3F1EC); apply the mint tint (fill + text) only to the chosen row. Pair with P1-4.
_Affected:_ all platforms, dark theme.

**P1-3 · Tablet screens stretch full-width instead of the documented tracks (UI:Layout, IxDF:Usable, Mobile:Platform).**
`DESIGN.md` promises tablets "use the width intentionally": Reports as a centered `readableMaxWidth` (760) column, the audit wizard with a **persistent left step sidebar** and the form capped at `formMaxWidth` (600), detail screens centered. The screenshots show none of this:

- `ipad/light · audit-domain-questions` renders the **phone single column with horizontal step pills**, form edge-to-edge (~2000px wide), producing very long line lengths.
- `ipad/light · reports` and `ipad/light · report-detail` stretch full-bleed with enormous full-width buttons; no 760 centering.
- `ipad/light · places` is one stretched full-width column.
  _Fix:_ apply `lib/responsive-layout.ts` tracks that already exist — `getResponsiveContentContainerStyle` with `readableMaxWidth`/`formMaxWidth`, and the tablet sidebar branch — to these routes. This is the single biggest gap between the documented design and what ships.
  _Affected:_ iPad + Android tablet, both themes.

**P1-4 · Selection carried by color alone in audit options (WCAG:ColorOnly, Norman:Signifiers).**
The selected option is indicated only by fill color, with no shape/icon change — invisible to color-blind users and low-signal in bright field light. _Fix:_ add a filled check/radio-dot or a 2px `ring` border on the selected row in addition to the tint. Effort S.

**P1-5 · Audit step pills: sub-44pt targets, hard-clipped last step (Mobile:TouchTarget, Norman:Discoverability, Nielsen:H6).**
The horizontal step-pill strip is ~30px tall (below the 44pt minimum the design system itself mandates) and clips the final pill with no scroll affordance, so later steps aren't discoverable as tappable. _Fix:_ min height 44pt; add an edge fade / peek so the strip reads as scrollable on phones; show all pills on tablet. Also use `radii.button` (10), not `full`.
_Affected:_ all phones; tablets show more pills but still clip the last.

**P1-6 · Gated "Submit audit" looks fully actionable (Nielsen:H5, Norman:Feedback).**
On Review & submit, the dark-primary **"Submit audit"** appears both inside the "Quick actions" card _and_ in the fixed footer, at full primary emphasis, while the amber note says "Context still needs required answers before this audit can be submitted." Two identical primary CTAs that will fail invite a dead-end tap. _Fix:_ keep one Submit (footer), drive it from `AppButton` `disabled`/`loading` state, and make the incompleteness a single inline reason next to it. Effort S–M.

### P2 — minor (worth doing)

**P2-1 · Redundant stacked status blocks (Krug:HalfTheWords, Nielsen:H8, IxDF:Space).**
Home stacks an "Online and ready to sync" card **and** a "READY FOR OFFLINE USE" banner before any action. Execute stacks an "ONLINE / All changes are synced" banner **and** a "Ready for offline capture" card — and "Ready for offline capture" is printed twice on that screen. Two reassurance blocks consume the first screenful and push real content below the fold. _Fix:_ one `StatusBanner` that expresses connectivity + offline-readiness + pending-sync together.

**P2-2 · Dark-mode hero inversion + mint-on-mint button (UI:Color, WCAG:Contrast, Nielsen:H4).**
Home's "Your assigned places" workflow card flips to a bright mint fill in dark mode — a large luminous block in an otherwise near-black screen — and its secondary "Continue draft" button is mint-on-mint (low contrast). _Fix:_ in dark, use a `surface`-level card with a mint accent border rather than a full mint fill; give the secondary button a distinct `surface`/`ghost` treatment.

**P2-3 · Duplicated / heavy list actions (Nielsen:H4, UI:Component).**
Reports gives every list row its own full-width "Open report" button while the featured card says "Open selected report" — inconsistent labels for the same action, and one heavy button per row. _Fix:_ make rows tappable via the `ListRow` primitive with a chevron; reserve the full-width `AppButton` for the featured card only. On tablet these buttons balloon full-bleed (see P1-3).

**P2-4 · "Not answered" uses the positive brand pill (Norman:Mapping, UI:Color).**
On Review (Youth-weighting rows) and Report detail, "Not answered" renders as a dark-green `primary` pill — the brand's _positive/done_ color used for a _missing_ value. _Fix:_ neutral (`surfaceMuted` + `mutedForeground`) or `warning` tone for absent answers; reserve primary for completed/affirmative.

**P2-5 · Report detail shows two identical bars per section (IxDF:Words, UI:Data, Krug:DontMakeMeThink).**
Each section renders a "Raw score" bar and a "Youth-Weighted" bar that are visually identical in every section (86/86, 38/38, 50/50 …), doubling the chart height with no perceivable difference. The raw-vs-weighted distinction _is_ meaningful in the table below (e.g. Activity Spaces 10/26 vs 20/52) but not in the bars. _Fix:_ one bar per section; keep raw/weighted in the table, or annotate why the two bars differ when they do.

**P2-6 · Text-size control doesn't preview its effect (Norman:Signifiers, Nielsen:H6).**
The four sample "A"s in Settings → Text size are all the same size. _Fix:_ scale each glyph (Small→Larger) so the control demonstrates its outcome.

**P2-7 · No feedback on the header refresh action (Nielsen:H1, Norman:Feedback, Mobile:Feedback).**
Tapping the Home header refresh icon gives no visible spinner/rotation. _Fix:_ rotate the icon / show `AppButton` loading state during sync.

**P2-8 · Step-completion mapping is inconsistent (Nielsen:H4, Norman:Mapping).**
On step 1 (Context, "1/8"), step 3 "Access" already shows a completed checkmark while earlier steps don't — the completed-state logic doesn't match linear progress, which is confusing. _Fix:_ reconcile the pill "complete" state with actual answered/required status; consider a single consistent rule (answered-required = complete).

### P3 — cosmetic / polish

- **P3-1 · Metric-card inconsistency (UI:Consistency).** Home metric tiles have colored soft borders + pill labels; Execute metric tiles are plain white with no border/pill. Pick one `MetricCard` treatment and reuse it. Label chips also use `full` radius where `radii.button` would match the system rule.
- **P3-2 · Near-empty "Audit results" card (Nielsen:H8).** On Report detail, the "Audit results / Scores and responses for this submitted audit." card is a title-only card that restates the page title "Report overview". Fold it into the header or drop it.
- **P3-3 · "Back to My Audits" as primary (Norman:Mapping).** On Report detail the dark-primary button is a _back_ action while "Share" is secondary. Navigation/back shouldn't out-rank the screen's real action. Swap emphasis (Share primary) or make Back a `ghost`/header affordance.
- **P3-4 · Redundant "Submitted" wording (IxDF:Words).** Report detail row label "Submitted at" pairs with value "Submitted Mar 15 at 9:50 AM" — drop the value's leading "Submitted".

## Dark mode

- Overall dark theme is well-built (true near-black `background` #141513, legible `foreground` #F3F1EC, sensible tinted surfaces). Issues are localized: **P1-2** (option labels in mint), **P2-2** (mint hero + mint-on-mint button), and secondary/caption text that drops toward AA on the darkest surfaces (audit "Save…" secondary, date subtitle on Home). Verify `mutedForeground` #A7A99F on `background` #141513 (~4.8:1, borderline for small text) and prefer `secondaryForeground` #C9C8BF for anything smaller than 16px semibold.

## Tablet / responsive

- The central problem is **P1-3**: the responsive machinery described in `DESIGN.md` (and present in `lib/responsive-layout.ts`) isn't applied to most routes, so iPad/Android-tablet render stretched phone columns with full-bleed buttons and long line lengths. Home reportedly also wastes vertical space by stacking status/offline instead of using its documented grid. This is the highest-ROI structural work: the tokens/utilities already exist; they need to be wired into Reports, Report detail, Settings, Execute, Places and the audit wizard.

## Accessibility

- **Good intent, uneven execution.** Ships OpenDyslexic + a 4-step text scale (with a 1.3× tablet multiplier) and routes text through `ScaledText`/`ScaledParagraph` — genuinely above-average. But: fill-as-text contrast failures (**P1-1**), color-only selection (**P1-4**), sub-44pt step pills (**P1-5**), and the dark option ambiguity (**P1-2**) are real AA gaps. Add: verify the densest surfaces (Report detail tables, long forms) survive "Larger" + 1.3× without clipping; confirm every icon-only control (header refresh/gear, back chevrons) has an `accessibilityLabel`.

## What's working — keep it

- **Clear type hierarchy & spacing rhythm** on phone (big display headings, comfortable 28px section gaps, safe-area handling under the Dynamic Island).
- **Thumb-zone primary actions** — every task screen puts its primary CTA in a fixed bottom footer.
- **Offline-first is front-and-center** and reassuring (once de-duplicated).
- **Coherent brand voice** — the warm-green system reads as one product; badges, cards and buttons share a family.
- **Real accessibility affordances** (dyslexia font, text scaling) that most field apps skip.

**Quick wins (< 1 day, mostly `S`):** P1-1 (fill→text tokens), P1-2 & P1-4 (dark option color + non-color selected state), P1-6 (single gated Submit), P2-6 (scaling "A"s), P2-7 (refresh feedback), P3-4 (drop duplicate "Submitted"). Highest quality-per-hour in the whole list.

**This sprint (`M`):** P2-1 (unify status into one `StatusBanner`), P1-5 (step-pill size + scroll affordance), P2-3 (ListRow-based reports), P2-4 (Not-answered tone), P2-5 (single bar per section), P2-8 (step-completion logic), P3-1 (unify `MetricCard`).

**Larger bet (`L`):** P1-3 — wire the documented responsive tracks (`readableMaxWidth`/`formMaxWidth`, tablet audit sidebar, Home grids) into every route so the tablet build matches its own spec. Do this once, centrally, and most tablet findings resolve together.
